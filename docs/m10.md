# M10 — Virtual devices, sensors, media, connectivity, and dynamic system config

Status: ✅ **implemented** (`MEDIA-01..08`, `NET-05..06`, `SYS-07`, `AG-10`).
Every M10 subsystem runs deterministically in pure safe Rust per `Engine`
instance with zero host OS hardware access, zero `unsafe` in `rd-vm` / `rd-agent`,
and full integration with Dalvik DEX callbacks, permission checks, and the MCP
agent surface.

Design decision record: [ADR 011](adr/011-m10-virtual-devices.md).

## Architecture

```text
 MCP client / rd test
   │  device_profile({ "action": "location" | "sensor" | "battery" | ... })
   ▼
 rd-agent::m10_tools ── validates arguments, materializes Engine, bumps ui_epoch
   │
   ▼
 rd-vm::m10 (per-Engine State)
   ├── sensors.rs       MEDIA-01  SensorManager, 8 Moto E5 sensors, SensorEventListener
   ├── location.rs      MEDIA-02  LocationManager, FusedLocationProviderClient, Haversine, routes
   ├── camera.rs        MEDIA-03  Camera2, CameraCaptureSession, ImageReader RGBA8888/JPEG
   ├── biometrics.rs    MEDIA-04  Framework + AndroidX BiometricPrompt, FingerprintManager
   ├── media.rs         MEDIA-05..08  AudioManager/Record/Track, MediaPlayer, MediaSession, MediaProjection
   ├── connectivity.rs  NET-05..06  Connectivity/Telephony/SMS, Bluetooth LE scan+GATT, NFC NDEF
   └── sysconfig.rs     SYS-07    Battery/PowerManager WakeLock, dark mode/locale/scale/orientation, Clipboard
```

- **Per-`Engine` isolation (Law 2 & Law 9).** All virtual peripheral state lives
  in `Engine.fw.m10` (`crates/rd-vm/src/m10/mod.rs`). No `thread_local!`, global
  singletons, or host OS hardware calls exist anywhere in M10.
- **GC-safe transient payloads.** High-frequency callback objects (`SensorEvent`,
  `Location`, `ImageReader` planes, `ScanResult`, `NdefMessage`, `ClipData`)
  store payloads directly in VM heap fields and primitive arrays so the
  mark-compact GC collects them automatically without unbounded host maps.
- **Coexistence with Appendix C absent-hardware defaults.** Raw `Engine::new()`
  starts with `m10.virtual_hardware_enabled = false` so Appendix C's sensorless /
  camera-less / radio-less unit-test profile stays intact. Launching an app
  through `rd-agent` (`AgentSession`), calling `Engine::m10_enable_virtual_devices()`,
  or invoking any `AG-10` mutation enables virtual peripherals ahead of the
  absent-hardware stubs in `crates/rd-vm/src/intrinsics.rs`.
- **Stable 47-tool MCP catalog.** `AG-10` multiplexes 18 `action` modes onto
  `device_profile` (`crates/rd-agent/src/m10_tools.rs`), preserving the locked
  47-tool MCP contract (`docs/mcp-tools.md`) and the no-app Moto E5 floor
  response when `action` is omitted or `"get"`.

## Feature flags

| Crate | Feature | Default | Effect |
|---|---|---|---|
| `rd-vm` | `virtual-devices` | on (implies `advanced-components`) | Enables `crates/rd-vm/src/m10/` and interpreter/intrinsic dispatch |
| `rd-agent` | `virtual-devices` | on | Enables `AG-10` `device_profile` mutations and live `virtual_devices` snapshot |
| `rd-cli` | `virtual-devices` | on | Forwards `virtual-devices` to `rd-vm` and `rd-agent` |

When compiled with `--no-default-features`, `device_profile` still serves the
read-only Moto E5 profile (`virtual_devices: null`) and returns typed
`NOT_IMPLEMENTED` on mutating `action`s.

## Supported surface

| Spec ID | Subsystem | Guest APIs |
|---|---|---|
| `MEDIA-01` | Virtual sensors | `SensorManager` (`getDefaultSensor`, `getSensorList`, `registerListener`, `unregisterListener`), `Sensor`, `SensorEvent` (`values`, `accuracy`, `timestamp`) for accelerometer, gyroscope, magnetometer, light, proximity, pressure, gravity, step counter |
| `MEDIA-02` | Virtual GPS & routes | `LocationManager` (`getLastKnownLocation`, `requestLocationUpdates`, `removeUpdates`, `isProviderEnabled`), `Location` (`distanceBetween` / `distanceTo` / `bearingTo` Haversine), `LocationServices.getFusedLocationProviderClient` (`getLastLocation`, `requestLocationUpdates`, `removeLocationUpdates`) |
| `MEDIA-03` | Virtual Camera2 | `CameraManager` (`getCameraIdList` back `"0"` + front `"1"`, `getCameraCharacteristics`, `openCamera`), `CameraDevice` (`createCaptureRequest`, `createCaptureSession`, `close`), `CameraCaptureSession` (`capture`, `setRepeatingRequest`), `ImageReader` (`acquireLatestImage`, `Image.getPlanes`, `Plane.getBuffer` `ByteBuffer`) |
| `MEDIA-04` | Programmable biometrics | `BiometricManager.canAuthenticate`, `android.hardware.biometrics.BiometricPrompt` + `androidx.biometric.BiometricPrompt` (`authenticate` -> `onAuthenticationSucceeded` / `onAuthenticationFailed` / `onAuthenticationError`), legacy `FingerprintManager` |
| `MEDIA-05` | Virtual audio | `AudioManager` (`requestAudioFocus`, `abandonAudioFocusRequest`, stream volumes, ringer mode), `AudioRecord` (deterministic PCM queue / synthetic sine wave; `RECORD_AUDIO` enforced), `AudioTrack` (PCM capture sink) |
| `MEDIA-06` | `MediaPlayer` | State machine (`Idle` -> `Initialized` -> `Prepared` -> `Started` / `Paused` / `Stopped` / `Completed` -> `Released`), `prepare`, `prepareAsync`, `seekTo`, `OnPreparedListener`, `OnCompletionListener`, `OnSeekCompleteListener` |
| `MEDIA-07` | `MediaSession` | `MediaSession` (`setCallback`, `setPlaybackState`, `setMetadata`, `setActive`), `PlaybackState.Builder`, `MediaMetadata.Builder`, `MediaController.TransportControls` (`play`, `pause`, `stop`, `seekTo`, `skipToNext`, `skipToPrevious`) |
| `MEDIA-08` | `MediaProjection` | `MediaProjectionManager` (`createScreenCaptureIntent`, `getMediaProjection`), `MediaProjection` (`createVirtualDisplay` backed by `rd-render` framebuffer dimensions, `registerCallback`, `stop`) |
| `NET-05` | Connectivity, telephony & SMS | `ConnectivityManager` (`getActiveNetwork`, `getNetworkCapabilities`, `registerDefaultNetworkCallback`), `TelephonyManager` (SIM/operator/network type/call state), `SmsManager.sendTextMessage` (`SEND_SMS` enforced), inbound `SMS_RECEIVED` broadcast + `Telephony.Sms.Intents.getMessagesFromIntent` |
| `NET-06` | Bluetooth LE & NFC | `BluetoothManager` / `BluetoothAdapter`, `BluetoothLeScanner` (`startScan` / `stopScan` with `BLUETOOTH_SCAN` check), `BluetoothDevice.connectGatt`, `BluetoothGatt` (`discoverServices`, `readCharacteristic`, `writeCharacteristic`), `NfcAdapter` (`enableReaderMode`, `ACTION_NDEF_DISCOVERED` -> `Activity.onNewIntent`), `NdefMessage` / `NdefRecord` |
| `SYS-07` | Battery, power, config & clipboard | `BatteryManager.getIntProperty` + sticky `Intent.ACTION_BATTERY_CHANGED`, `PowerManager` (`isInteractive`, `isPowerSaveMode`, `newWakeLock` acquire/release refcount), dark mode (`Configuration.uiMode`), locale (`Locale.getDefault`), font scale, orientation (`Activity.onConfigurationChanged`), `ClipboardManager` (`ClipData` synchronized with `m9_ime`) |

## MCP `AG-10` actions on `device_profile`

All virtual peripherals are inspected and mutated through `device_profile`:

- `{"action": "get"}` (or `{}`): Moto E5 hardware floor + live `virtual_devices` object (`null` before launch)
- `{"action": "location", "latitude": -23.55, "longitude": -46.63, ...}` or `{"action": "location", "route": [...]}` / `{"action": "location", "step_route": true}`
